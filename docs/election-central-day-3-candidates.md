# Election Central — Day 3 candidate system

## Architecture

Candidate pages are generated by the single
`/elections/candidates/$candidateSlug` route. Repository adapters return a
`CandidateDetail`; the route composes reusable profile sections. Adding a
candidate must never require creating a new route or manually designed page.

The public directory links each `CandidateSummary.slug` to the same reusable
profile route.

## Structured profile fields

Every candidate detail contract includes:

- name and party
- primary race and district context
- campaign and candidate websites
- current office and sourced office history
- basic biography
- image URL, alt text, and usage-rights metadata
- social links
- campaign-finance URL and optional finance summary
- a source-reference list
- repository verification timestamp
- `standard` or `expanded` profile depth

Unavailable optional information is labeled as unavailable. It must not be
filled with invented text or placeholder election data.

## Image policy

Candidate images render publicly and enter SEO metadata only when
`imageRights.usageStatus` is `approved`. Restricted or unknown images fall back
to candidate initials. Adapters must provide a source URL and should provide
credit and license information whenever an image is approved.

## Source policy

All external URLs are restricted to HTTP or HTTPS. The profile displays the
structured source list and last verification date. If an adapter has not yet
populated the source list, the normalized record source is shown as the
minimum attribution.

## Standard profiles

Standard profiles use the shared biography, campaign links, office history,
race, polling, results, sources, and internal-link sections. This is the
default depth for directory candidates.

## Expanded statewide profiles

Set `profileDepth` to `expanded` only through structured repository data.
Expanded profiles add campaign-finance metrics and sourced endorsement
coverage. Major statewide candidates should be the first records reviewed for
expanded status. The same template remains in use; no candidate-specific page
component is permitted.

Expanded content must remain source-backed. A missing finance summary or
endorsement list produces an explicit no-data message rather than fabricated
content.

## Adapter checklist

Before publishing a candidate:

1. Resolve the candidate to a published race and district or statewide context.
2. Verify the name, party, biography, office history, and campaign links.
3. Confirm image usage rights before setting the image status to `approved`.
4. Add campaign-finance and social URLs only from public sources.
5. Populate the source list and verification metadata.
6. Choose `expanded` depth only after the deeper fields have editorial review.
7. Confirm the generated directory card and profile route without adding a new
   page file.

No person-level voter registration or ballot-tracking data belongs in the
candidate model.
